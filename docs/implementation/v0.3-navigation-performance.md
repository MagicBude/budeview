# V0.3 Navigation & Performance

## 目标

把 V0.2 的“能看图”推进到“连续看图时基础体验成立”。

## Preload

默认候选范围为当前图 ±2。

方向提示：

- 向右浏览：`+1, +2, -1, -2`
- 向左浏览：`-1, -2, +1, +2`
- 初次打开：`+1, -1, +2, -2`

任何新导航都会取消旧 Preload。

## Preload Admission

Preload 是 speculative work。

规则：

- 当前图片永远优先。
- 当前图片可以为了进入缓存而触发 LRU 淘汰。
- Preload 不会为了自己驱逐已经存在的有效缓存。
- 如果预算不足，预载结果直接丢弃。
- 因此超大 8K 图不会为了“预载数量”强迫进程无限增大。

## Cache Budget

默认预算按可用内存的约 1/32 计算，并限制在：

- 最低：256 MiB
- 最高：512 MiB

该值是 Decode Cache 上限，不代表进程总 Working Set 上限。

## Fullscreen

使用 Avalonia `WindowState.FullScreen`。

F11 进入/退出；Esc 退出。

临时开发 Toolbar / Status Bar 在 Fullscreen 中隐藏。

## Render Trace

V0.2 的 `present_requested` 只能说明 Viewer 已请求显示。

V0.3 在 `ViewerSurface.Render()` 第一次真正绘制新内容时记录：

`image_rendered`

Startup Benchmark 以此作为 First Image 基线。

## Startup Benchmark

`scripts/benchmark-startup.ps1`

流程：

1. Native AOT publish。
2. 启动正式 EXE。
3. 打开固定图片。
4. 首帧绘制后自动退出。
5. 记录 Window、First Image、Decode、Peak Working Set。
6. 输出 P50 / P95 和 CSV。

该 Benchmark 只用于同版本回归，不用于与早期技术选型仓库直接横向比较。
